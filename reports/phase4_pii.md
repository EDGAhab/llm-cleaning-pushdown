# Phase 4 计划：PII 合规场景（检查点 2 转向）

日期：2026-09-24。状态：数据已建好并验证，矩阵已启动。

## 为什么转向

检查点 2 结论：C 在唯一带宽可比配置上对 E 只有 1.9% 的单次 time 优势（噪声级），
E 成本大胜；低配额下 C 被 A 拉开 1.6–6.2 倍。C vs E 没有稳健优势。
按 handoff §8，论文重心转向 **PII 合规场景** 与 **"下推的边界"**。

场景一（handoff §2）：企业用内部敏感数据做微调，在存储端先做 PII 脱敏，
原始数据不出存储。这里下推的价值不是"更快/更便宜"，而是**合规**：
PII 在存储端就被 redact，永远不以原文形式离开存储。

## 本阶段回答的两个问题

1. **合规溢价**：把 PII 关在存储里（C），相对现行做法全拉取（A），
   要多付多少 time_to_ready 和美元成本？E（同区域 CPU 集群）作为最强基线。
2. **密度边界**：PII 密度上升时，redact 的 CPU 开销上升，下推划算/可行的
   边界如何移动？配额扫描（q10/q25/q50）在 d10 上回答配额边界。

## 数据（已建成并验证）

构建脚本：`scripts/40_pii_data.py`。输出：`data_pii/<tier>/` + `data_pii/manifest.json`。

- 基座：`data/_dl/fw_shard.parquet` 前 20k 非空文档，三个 tier 共用**完全相同**
  的基座文档，tier 间唯一变量是注入的 PII 密度。
- **预清除**（修复 checkpoint 1→2 遗留项）：用 pipeline 的**原样正则**
 （从 `plugins.cleaning` import，非复制）扫描基座，把 3,076 个 FineWeb 原文
  自然 PII 形匹配替换为 `[PRECLEARED]`。之后 `pii_redactions` 计数即为纯合成注入。
- 注入（预清除**之后**，两者无交互）：
  - d01：1% 文档 ×1 个 = 208 个
  - d10：10% 文档 ×1 个 = 1,970 个
  - d30：30% 文档 ×1–3 个 = 12,001 个
- **验证**（脚本内自动，失败即 abort）：对每个 tier 文件用真正的 `pii_redact`
  重跑，断言 redact 总数**精确等于**注入数，且 redact 后无 PII 形残留。
  三个 tier 全部通过（208/1970/12001 精确命中）。

### 构建中发现并修复的测量 artifact（诚实记录）

`00_prepare_data.py` 的合成电话模板 `"555-01XX"` 是 7 位数字，而 pipeline 的
`PHONE_US_RE` 只匹配 10 位 NANP 号码——**week-3/week-4 数据里的合成电话从未被
`pii_redact` 捕获**，属于静默漏检。本阶段模板已修正为 `(415) 555-01XX`
（10 位，保留虚构号段 555-01XX），验证通过。旧数据的该问题已在检查点报告
的"计数污染"项下披露口径内，不追改旧结果（旧结果与旧数据绑定）。

## 实验矩阵（已启动）

脚本：`scripts/run_pii_matrix.sh`，输出：`experiments/pii_matrix/`。

| tier | 运行 | 带宽 | 目的 |
|---|---|---|---|
| d01/d10/d30 | A | 100Mbps | 现行做法基线（原文出存储） |
| d01/d10/d30 | C q25 | 100Mbps | 合规方案（存储端 redact） |
| d01/d10/d30 | E | 10Gbps | 最强基线（同区域 CPU） |
| d10 | C q10 / q50 | 100Mbps | 配额边界扫描 |

共 11 runs，单 run 约 20 分钟（2vCPU），断点续跑。跑完自动生成
`report.md` + `cost_onepager.md`。

## 合规指标（派生，无需新埋点）

- **未脱敏 PII 出存储量**：A/E 先拉原文后在计算端 redact ⇒ 暴露量 = 该 tier
  注入总数（manifest 精确值）；C 在存储端 redact ⇒ 暴露量 = 0。
- **合规溢价**：同 tier 下 `time_to_ready(C q25) / time_to_ready(A)`、
  `cost_usd` 差值。
- **密度边界**：`storage_cpu_s` 与 `pii_redactions` 随 tier 的变化；
  C q25 的 time 劣势是否随密度扩大。

## 诚实性备注（先写下）

1. 20k 文档子集、单次测量、无重复——所有比值无误差棒。
2. 单机模拟：存储/计算同机，传输时间为带宽模型；绝对时间不可外推云上。
3. cost_usd 仍为占位定价（week8 才收真实云定价）；E 便宜的方向性结构成立，
   幅度不作结论。
4. 预清除改写了原文（3,076 处 → `[PRECLEARED]`），基座文本不再是原始 FineWeb；
   但所有 scheme 共用同一数据，横向比较成立；正确性要求（各 scheme 输出
   sha 一致）不受影响。
5. 合规暴露量指标假设"合规 = PII 不出存储"；不讨论加密传输等替代合规手段，
   会在论文 limitations 中说明。
